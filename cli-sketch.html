ID grammar

Every command except cache takes one positional ID. IDs use a typed-prefix scheme so files, projects, comments, and nodes are syntactically distinct — no magic-number ranges, no shape clashes.

ID ::= TAG ":" REST | NUM ":" NUM # bare native node id (file-scoped; lenient lookup) | URL # escape hatch — always works TAG ::= "proj" | "file" # active today | "comm" | "user" | "var" # reserved for future entity types | "style" | "comp" REST ::= NUM # e.g. file:2 → a file | NUM ":" NUM ":" NUM # e.g. file:2:1094:66591 → a node in a file | NUM ":" TAG ":" ID_BODY # e.g. file:2:comm:abc → comment inside file NUM ::= [0-9]+ URL ::= "https://" .*figma.com.* # node-id query param normalized 1094-66591 → 1094:66591

Parsing rule: peek the first token before :. If it's a known tag → typed ID, dispatch on the tag. If both halves are numeric → bare native node ID, resolve via cache lookup. Else if it starts with https:// → URL.

Synth IDs (proj:N, file:N) are assigned by the cache. N is a small sequential integer, stable across cache reads (persisted in the manifest). New files get the next free N; deleted files leave gaps.

Native node IDs stay in Figma's x:y shape inside the qualified form (file:N:x:y). When you paste a Figma URL or copy a node-id from Figma's UI, the parts are recognized natively.

Global flags & output rules

FlagEffect
--jsonEmit full JSON with metadata headers. Default is compact YAML.
--token <TOKEN>API token. Falls back to FIGMA_TOKEN.
--cache-onlyRefuse to fall through to the live API. Errors if the cache can't satisfy the request.
--in <ID>Scope a bare node ID. Used to disambiguate 0:0-class collisions. Accepts file:N or file:N:x:y.

Output convention: every line emits a fully qualified ID (file:N:x:y rather than bare x:y) so any line is paste-safe into another command, regardless of which file it came from.

Line format:

ID  BOUNDS_OR_ANCHOR  | [indent]TYPE  "NAME"  ["CONTENT"]  [extras]

Column 1 (ID) and column 2 (bounds/anchor) are padded to the local max width per listing so the pipe lands at a fixed position. The pipe is the visual rail and a clean awk split point. Depth indentation lives after the pipe, in column 3. Long fields — names, content, comments — sit at the tail where they can run arbitrarily without disturbing the rail.

Bounds render as WxH@X,Y (no internal whitespace). Nodes without a bounding box (DOCUMENT, virtual nodes) and entities that aren't spatial (projects, files) show -. Comment anchors render as @<node-id>.

Pipes inside "…" are content; pipes outside quotes are delimiters.

Parsing recipes:

ToolResult
awk '{print $1}'IDs
awk '{print $2}'bounds/anchors
awk -F'|' '{print $2}'the indented content half (TYPE + name + …)
awk -F'"' '{print $2}'names
awk -F'"' '{print $4}'content (when present)
grep file:2:1094:66591that node + all descendants (their IDs share the prefix)

Bare IDs & ambiguity

A bare x:y is convenient — it's what you copy out of Figma's UI. The CLI is lenient: bare IDs get looked up against the cache's node_id → [file_synth] index.

  • Exactly one cached file contains it → use it.
  • No cached file contains it → suggest pasting a URL (file may not be cached).
  • Multiple cached files contain it → error with candidates, ask for qualified form.

Collisions concentrate at low IDs. Empirically across 50 cached files:

  • 0:0 exists in all 50 (DOCUMENT root)
  • Low-x canvases (0:1, etc.) overlap heavily
  • Deeper node IDs (1094:66591-class) almost never collide

Ambiguity error example

$ figma tree 0:0
error: node 0:0 exists in 50 cached files.
       Disambiguate with --in or paste a URL. Top candidates:
         file:1   FILE "404 / No Access"
         file:2   FILE "Admin Module"
         file:3   FILE "Allowances"
         file:4   FILE "Booking Leave"
         ... 46 more (see `figma ls`)
       Try:  figma tree file:2:0:0
       Or:   figma tree 0:0 --in file:2

What changes from today

Removed
  • find (single-token fuzzy across all names) — its job is absorbed by the renamed multi-token search.
  • tree — merged into ls --depth N. The default depth for ls bumped to 3; deep dumps use --depth 6 (or whatever).
  • --file-key, --node-id, --url, --page, --frame flags. Everything is the single positional ID.
  • Separate pages / frames / files commands. Replaced by ls at depth N.
  • The compound FILE_KEY:NODE_ID locator shape. Replaced by tagged IDs.
Renamed
  • search → find (the only name-aware command left)
  • extract-assets → assets
  • styles → tokens

ls

List a node and its descendants. Default depth = 3 — the node, its children, and their children's children. Use --depth to go shallower (orient quickly) or deeper (render the whole subtree).

Usage

figma ls [ID] [--depth N]

Special cases

  • No ID: lists projects from the cache manifest, with files grouped under each. Read-only on the cache; no API calls.
  • file:N: depth starts at the file root (DOCUMENT node). Depth 1 = pages; depth 2 = pages + frames; etc.
  • file:N:x:y: depth starts at that node.
  • Bare x:y: resolved via cache lookup (lenient).
A bare file:N ID without explicit --depth uses depth 1 (just pages) — going deeper on a large file can flood the output (some files in your cache have 80k+ nodes). Pass --depth N deliberately when you want more.

find

Multi-token ancestor-chain name search. Each whitespace-separated query token must fuzzy-match some name along the root→node path; leaf hits score highest. Output is ranked, with each line's leading column being a paste-ready fully-qualified ID.

Usage

figma find QUERY... [--in ID] [--type T1,T2,...] [--limit N]

Example 1 — global search (whole cache)

$ figma find wallchart filter button
file:2:1094:71203  120×40@24,12   | INSTANCE  9.2  "Filter Button"   (Wallchart > Header > Filters)
file:2:1094:71215  80×40@164,12   | INSTANCE  8.8  "Filter Reset"    (Wallchart > Header > Filters)
file:2:1094:71400  1440×64@0,80   | FRAME     7.4  "Filters"         (Wallchart > Header)
file:5:312:8801    100×32@12,12   | INSTANCE  7.1  "Filter"          (Calendar > Sidebar)

Example 2 — scoped to a file

$ figma find filter button --in file:2
file:2:1094:71203  120×40@24,12   | INSTANCE  9.2  "Filter Button"  (Wallchart > Header > Filters)
file:2:1094:71215  80×40@164,12   | INSTANCE  8.8  "Filter Reset"   (Wallchart > Header > Filters)
file:2:1094:71400  1440×64@0,80   | FRAME     7.4  "Filters"        (Wallchart > Header)

Example 3 — scoped to a subtree, with type filter

$ figma find button --in file:2:1094:66591 --type INSTANCE --limit 5
file:2:1094:66603  140×40@1276,20 | INSTANCE  9.0  "Add Employee"   (Header)
file:2:1094:67205  60×32@1100,16  | INSTANCE  8.4  "Next"           (Pagination)
file:2:1094:67206  60×32@1170,16  | INSTANCE  8.4  "Previous"       (Pagination)
file:2:1094:66616  80×40@524,12   | INSTANCE  7.2  "Clear"          (Filters)

screenshot

Render a node as PNG/JPG/SVG/PDF. Without --out, prints the source URL — no bytes are downloaded.

Usage

figma screenshot ID [--img-format png|jpg|svg|pdf] [--scale F] [--out PATH]

Example 1 — write a file

$ figma screenshot file:2:1094:66600 --out header.png --scale 2
file:2:1094:66600 → header.png  (PNG, 24 KB)

Example 2 — just the URL

$ figma screenshot file:2:1094:66600
id:  file:2:1094:66600
url: https://s3-figma-rendered-images.figma.com/.../abc123.png

Example 3 — --json

$ figma screenshot file:2:1094:66600 --out header.png --json
{
  "id":         "file:2:1094:66600",
  "node_id":    "1094:66600",
  "file_key":   "48nDWkcsuJ8TdoEIW9LGl6",
  "wrote":      "header.png",
  "bytes":      24576,
  "source_url": "https://s3-figma-rendered-images.figma.com/.../abc123.png"
}

tokens

Extract design tokens (colors, fonts, sizes, spacing, radii, shadows, grids). Pulls from the target's subtree and/or the file's published variables.

Usage

figma tokens ID [--scope target|file|both]
                     [--only CAT1,CAT2,...]
                     [--as tokens|css]

Example 1 — default tokens output

$ figma tokens file:2:1094:66591 --only colors,spacing
colors:
  bg-primary:   "#ffffff"
  bg-muted:     "#f6f8fa"
  text-primary: "#1f2328"
  text-muted:   "#57606a"
  accent:       "#0969da"
  danger:       "#cf222e"
spacing:
  xs: 4
  sm: 8
  md: 16
  lg: 24
  xl: 32

context

Bundled export: tree + screenshot + tokens + assets into one directory. The "give me everything to implement this frame in code" command.

Usage

figma context ID [--out-dir DIR]

Example

$ figma context file:2:1094:66600 --out-dir ./hero
id:      file:2:1094:66600
out_dir: ./hero

  - hero/tree.yaml         (1.2 KB)
  - hero/screenshot.png    (24 KB)
  - hero/tokens.yaml       (380 B)
  - hero/assets/           (12 icons, 3 images)
  - hero/manifest.json

cache

Prime / refresh the local file cache. The only command that doesn't take an ID. Walks every configured project, refetches files whose lastModified changed, and persists the synth-ID mappings (proj:N / file:N) in the manifest.

Usage

figma cache [--projects IDS] [--force] [--concurrency N] [--dir PATH]

Example — incremental refresh

$ figma context file:2:1094:66591 --out-dir ./employees

$ figma tokens "https://www.figma.com/design/48nDWkcsuJ8TdoEIW9LGl6/Admin?node-id=1094-66591" --as css
# → :root { --color-bg-primary: #ffffff; ... }

$ figma find Employees --type CANVAS --limit 1
