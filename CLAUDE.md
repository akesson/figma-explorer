# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workspace

Cargo workspace with three crates:

- **`figma-api/`** — autogenerated Rust client for the Figma REST API. **Do not hand-edit** `src/apis/` or `src/models/`; regenerate via `figma-api/scripts/regenerate.sh` (needs `npx` + JDK 11+). Drift fixes go in `openapi/patches/*.patch` or `scripts/postprocess.py`, not in the generated tree.
- **`figma-explorer/`** — the main CLI binary (`figma-explorer`). High-level navigation, screenshots, token/asset extraction, local cache.
- **`figma-get/`** — thinner read-only CLI over the same `figma-api` client.

## Commands

```bash
cargo build                                  # whole workspace
cargo build -p figma-explorer                # one crate
cargo test                                   # all unit tests
cargo test -p figma-explorer <name>          # single test by name substring
cargo fmt
cargo run -p figma-explorer -- <subcommand>  # run the CLI locally
```

The repo auto-loads `.env` via `dotenvy`, walking from cwd up to the filesystem root, then `$XDG_CONFIG_HOME`-or-`~/.config/figma-explorer/.env` as the lowest-priority global fallback (covers git worktrees that don't see the canonical checkout's `.env`). The closest `.env` wins; ancestors fill in keys it didn't define; the real environment beats them all. Required: `FIGMA_TOKEN`. Cache prefetch needs `FIGMA_PROJECTS_IDS` (comma-separated Figma folder IDs — Figma renamed projects to folders in Aug 2026, ids unchanged; listings go through `GET /v2/folders/{id}/files` with a one-shot v1 fallback on 403 for pre-rename tokens); `library search` and the `cache prefetch` catalog warm need `FIGMA_TEAM_ID`. Cache location override: `FIGMA_EXPLORER_CACHE_DIR` (else `dirs::cache_dir()`).

## Architecture — figma-explorer

**Tagged-ID grammar** (`src/id.rs`) is the one positional shape across every subcommand: `proj:N`, `file:N`, `file:N:x:y`, `file:N:comm:M`, `mark:<key>` (a curated keyword mark, see below), bare `x:y` (native Figma node id), or a full figma.com URL. Synthetic small integers (`proj:N`, `file:N`) replace Figma's long opaque identifiers and are persisted in `<cache-root>/synth.json` so they stay stable across runs (gaps are never reused).

**Resolver** (`src/resolver.rs`) is the single entry point that turns an `Id` into a `ResolvedTarget` (Root/Project/File/Node/Comment). It wraps the cache, the `SynthState`, a lazily-built `NodeIndex` (only constructed when a bare-node lookup actually needs it), and a lazily-loaded `MarkStore`. Comment ids (`file:N:comm:M`) resolve by reading the `.comments.json` sidecar; `node-info` and `comments` consume that variant — every other command rejects comment ids with a hint. Mark ids (`mark:<key>`) resolve through `marks.json`: a single-node mark collapses to `ResolvedTarget::Node` (so every node-accepting command works unchanged), while a multi-node mark returns `NotResolvableYet` listing the paste-ready ids.

**Local cache** (`src/cache.rs`) stores a slimmed structural projection per file as `files/{file_key}.rkyv` plus a `.meta.json` sidecar. There is **no central manifest** — every piece of per-file state lives in its own sidecar so concurrent writers on disjoint files never share a write path. On-disk payload format: `[4-byte magic "FXC\0"][u32 LE version][rkyv body]`; version mismatch → silent refetch. rkyv archives are not endianness-portable; the cache is single-machine. Multi-repo coexistence: prune operations only touch metas whose `project_id` is in the current process's `FIGMA_PROJECTS_IDS`.

Three sidecars live next to each file's rkyv payload:
- `{file_key}.comments.json` — pre-associated comments (`Vec<AssociatedComment>`).
- `{file_key}.full.json.gz` — full raw `/v1/files/{key}` body, gzipped (`src/full_cache.rs`). Read by `node-info` so it works offline without the rkyv projection dropping fields it needs. Stamped via `FULL_SCHEMA_VERSION` on the meta. Disable with `cache prefetch --no-full`.
- `{file_key}.variables.json` — local variables (`/v1/files/{key}/variables/local`). Paid-tier endpoint; `cache prefetch` auto-disables further variables fetches after 3 consecutive 403s in a single run and records the error on the meta. Disable with `--no-variables` or `FIGMA_EXPLORER_FETCH_VARIABLES=0`. `write_fetched` (so every version-check refetch) re-fetches it *only* for files whose meta already has `variables_fetched_at_epoch` — elsewhere the endpoint is a 403; a failed re-fetch keeps the old sidecar and `node-info` warns via `cache::variables_predate_payload`.

Two **root-level** state files live in the cache root, not under `files/`, so they survive `cache clear`: `synth.json` (synthetic-id assignments) and `marks.json` (curated keyword→node marks, `src/marks.rs`). `marks.json` mirrors `synth.json` structurally — versioned schema, `marks.lock` + atomic tempfile save, an fs2-locked `with_lock` (whose closure returns `Result`, saving only on `Ok` so a failed `mark add` doesn't rewrite the file). Marks store **native** `(file_key, node_id)` pairs plus a per-node `Stamp` (name + ancestor-name path + epoch); `check_freshness` compares the stamp against the current cached document to flag `[renamed]`/`[moved]`/`[gone]`/`[uncached]`. `find`/`library search` read it leniently (corrupt → no injection); `mark:<key>` resolution and `mark add/rm/list` go through it authoritatively.

One **team-scoped** sidecar lives outside `files/`: `teams/{team_id}.catalog.json.gz` — the published team-library catalog (components, component sets, styles) aggregated from `/v1/teams/{team_id}/{components,component_sets,styles}`, gzipped, versioned via `CATALOG_SCHEMA_VERSION`. It sits in `teams/` (parallel to `files/`) because it is keyed by team, not file. `src/team_catalog.rs` owns its model, projection, paginated fetch, and tolerant sidecar I/O; `library search` writes it lazily and `cache prefetch` warms it (`--no-catalog` to skip). Variables are absent — the Variables REST API is Enterprise-gated, so the catalog covers components/sets/styles but not color tokens. A full `cache clear` sweeps `teams/` alongside `files/`; `synth.json` and `marks.json` are preserved.

**Untyped JSON reads** (`src/cmd/mod.rs::fetch_file_json`): commands hit Figma's REST endpoint directly with `serde_json::Value` rather than going through `figma-api`'s typed deserializer, because real files routinely contain nodes the OpenAPI spec doesn't model. The cache projection (`CacheNode`) drops fields the structural commands don't need; `assets` still walks raw `Value` live for access to `fills`, and it and `screenshot` render through the `/images` API. `node-info` reads `fills`/`strokes`/`style`/etc. from the `.full.json.gz` sidecar instead of refetching live on every call.

**Resolve-then-fetch pattern.** Every subcommand follows the same two-step shape:

1. **Resolve** the tagged ID through `Resolver::resolve(cfg, &id)` → `ResolvedTarget`. Always cache-first, but **version-checked**: `Resolver::read_file_or_fetch` runs `cache::ensure_fresh` on the file first — at most once per `VERSION_CHECK_SECS` (5 min) per file it probes `GET /v1/files/{key}/meta` and compares `version` with `FileMeta::version`; a mismatch (or a pre-feature meta with no `version`) refetches via `write_fetched`, which rewrites payload + `.full.json.gz` + meta from one response (plus comments, and the variables sidecar when the file has one). A failed probe/refetch serves the existing entry (it deliberately does not go through `fetch_and_cache`'s failure marker, which deletes the payload); a 403/404 probe restamps the check time so unreadable files back off a full window instead of being re-probed by every sweep, and a failed refetch sets `FileMeta::refetch_failed_at_epoch` so for the rest of the window the file is neither probed nor refetched — each command just warns it is serving an out-of-date copy (one timeout per window, never silent). Bare `x:y` ids look up a `NodeIndex` built from unchecked payloads, so `resolve_bare` freshens all metas and rebuilds the index on a miss (index fingerprint includes `cached_at_epoch`, so any refetch invalidates it). Commands that sweep payloads straight from the cache — `find` without `--in`, `ls` root/project at depth ≥ 2 — call `Resolver::freshen` over the swept metas first; any new multi-file reader must do the same. The version check only covers files already cached, so `ls` root/project (any depth) and `find` without `--in` first call `Resolver::sync_folders` → `cache::sync_folders`: once any configured folder is past `VERSION_CHECK_SECS` (stamps: `folders/{id}.json`, swept by `cache clear`, also written by `cache prefetch`), it lists **all** configured folders — even for `ls proj:N`, since only the whole set tells a move from a deletion — then fetches new files (and retries `Failed` markers), updates renamed/moved metas in place (interning the destination `proj:N`), and deletes entries in no listing, but only when every listing succeeded. New files are fetched only for folders that already have cached files — populating an empty cache stays `cache prefetch`'s job. Only `FIGMA_PROJECTS_IDS` folders are synced (jurisdiction rule); every folder is stamped even on failure, so a broken one costs one request per window. `--cache-only` never probes and prints a staleness note instead. The only cold-fetch fallback is `cache::load_file`, invoked from inside `resolve_url` when a URL points at a file_key the cache has never seen. `load_file` returns the payload *and* the newly-interned file synth so the resolver does not need to reload `synth.json` from disk to learn what was just assigned.
2. **Fetch full data**, if the command needs fields the structural cache drops, via `cmd::fetch_file_json`. This is independent of step 1 — the resolved target supplies the file_key, then the command hits the live REST endpoint.

Which lane each subcommand uses:
- *Structural only* (no step 2): `ls`, `find`.
- *Resolve, then fetch live*: `screenshot`, `assets`. These need the `/images` API (and `assets` fields the cache drops), so there is nothing to serve offline — they refuse up front under `--cache-only` rather than resolving and then silently hitting the network.
- *Resolve, then read sidecar (with live fetch as fallback)*: `node-info` (consumes `.full.json.gz` for offline-correct paint/text/effect data; refetches the whole file via `cache::refetch_file` when the sidecar is absent or `cache::full_sidecar_current` says it predates the payload, unless `--cache-only` is set); `comments` (consumes `.comments.json`; fetches live when the sidecar is absent or `--refresh` is passed — one file's comments, never a full prefetch). Comment activity does **not** change Figma's `version`, so the version check never sees it: `cache::ensure_comments_fresh` gives comments their own `VERSION_CHECK_SECS` clock (`FileMeta::comments_checked_at_epoch`, stamped on failure too so a dead endpoint costs one attempt per window). `comments` and `node-info` (when it shows comments) call it; `find`/`ls` read the sidecar as-is, since sweeping would cost one `/comments` call per file.
- *Cache plane*: `cache prefetch` bypasses the resolver entirely and writes meta+payload+sidecars by walking project listings.
- *Team-catalog plane*: `library search` also bypasses the resolver — it takes no tagged ID. It reads the team-scoped catalog sidecar, lazily fetching from the team-library endpoints when the sidecar is absent or older than `CATALOG_TTL_SECS` (24h; `--refresh` forces it).

New subcommands should pick one of these lanes deliberately rather than hand-rolling a third path.

## Releases

Tag-driven via [cargo-dist](https://opensource.axo.dev/cargo-dist/) (`dist` v0.32). Config lives in `[workspace.metadata.dist]` and `[profile.dist]` in the root `Cargo.toml`; the workflow at `.github/workflows/release.yml` is **generated** — re-run `dist init` and `dist generate` rather than hand-editing it.

- **Tag = version.** Pushing `vX.Y.Z` triggers the release; the tag must match `figma-explorer/Cargo.toml`'s `version` exactly or the workflow refuses. Bump the version, refresh `Cargo.lock`, merge, then tag.
- **Cargo.lock is committed** (binary distribution needs reproducible builds — do not re-add it to `.gitignore`).
- **Only `figma-explorer` ships.** `figma-get` and `figma-api` are `publish = false`.
- **Targets**: macOS arm64, Linux x86_64 (musl, static), Linux aarch64, Windows x86_64.
- **Channels**: GitHub Releases (always), Homebrew tap (`akesson/homebrew-tap`), npm (`@akesson/figma-explorer`), shell + PowerShell installer scripts. The tap repo needs at least one commit (a `main` branch) to exist or the publish job fails on first push.
- **macOS binaries are codesigned and notarized.** Two halves, because dist 0.32 does one and not the other:
  - *Signing* is dist's own: `macos-sign = true` makes `dist build` run `codesign` on each binary before it is archived, reading `CODESIGN_CERTIFICATE` (base64 .p12), `CODESIGN_CERTIFICATE_PASSWORD`, and `CODESIGN_IDENTITY` from the build job's env. Those exact secret names are hardcoded in the generated workflow — the older `MACOS_*`/`APPLE_SIGNING_IDENTITY` secrets are unused leftovers.
  - dist passes `--options $CODESIGN_OPTIONS` but offers no config for it, and **without `runtime` the hardened runtime is off and Apple rejects the binary**. `github-build-setup = "../build-setup.yml"` (path is relative to `.github/workflows/`; the file lives at `.github/build-setup.yml` because anything under `workflows/` gets run as a workflow) injects a step into `build-local-artifacts` that sets `CODESIGN_OPTIONS=runtime` via `$GITHUB_ENV`. dist does *not* pass `--timestamp`, but codesign applies a secure timestamp by default for Developer ID identities (verified), so that half needs no fix.
  - *Notarization* is ours: dist 0.32 has no notarization support at all, so `global-artifacts-jobs = ["./notarize-macos"]` adds the hand-maintained `.github/workflows/notarize-macos.yml` (like `publish-npm.yml`, **not** regenerated by `dist generate`). It re-verifies Developer ID + hardened runtime + timestamp before spending a submission, then `xcrun notarytool submit --wait` using `NOTARY_KEY_BASE64`/`NOTARY_KEY_ID`/`NOTARY_ISSUER_ID`. `dist generate` wires the release-creating `host` job to need it, so a rejection blocks the release.
  - **Nothing is stapled** — `stapler` only takes .app/.pkg/.dmg, never a bare Mach-O or a .tar.xz. The ticket lives on Apple's servers and Gatekeeper resolves it online at first run. The upside is that the artifacts are byte-identical before and after notarization, so checksums, the Homebrew formula, and the npm package stay valid. The tradeoff is that a *fully offline* first run on a quarantined download still warns.
  - Signing/notarization only runs on a real build, and `pr-run-mode = "plan"` means PRs never build. The only way to test a change here is a tag — use a prerelease tag (`vX.Y.Z-rc.1`), which builds and notarizes but skips the Homebrew/npm publish jobs.
- **npm publishes via Trusted Publishing (OIDC)**, not a token. dist's built-in `npm` publish job is replaced by the hand-maintained reusable workflow `.github/workflows/publish-npm.yml` (`publish-jobs = ["homebrew", "./publish-npm"]`), which gets `id-token: write` and runs Node 22 + npm ≥ 11.5.1 with **no** `NODE_AUTH_TOKEN` (a token, if present, silently overrides OIDC). The trusted publisher is registered on npmjs.com for `@akesson/figma-explorer` (owner `akesson`, repo `figma-explorer`, workflow `release.yml`). That file is not regenerated by `dist generate`; edit it directly. Provenance attestations are generated automatically.
- **PR sanity check**: `pr-run-mode = "plan"` runs `dist plan` as a check on every PR — surfaces config drift before it hits a tag.

**Global flags** (`Globals` struct in `lib.rs`) are threaded through every subcommand: `--json` (compact JSON; else YAML rendered by `src/yaml_out.rs` — block style for the tree skeleton, flow style for leaf containers, plain-scalar quoting that round-trips through YAML 1.1 parsers), `--cache-only` (refuse live API fallback, including the 5-minute version check), `--in <ID>` (scope override for bare-id resolution; only `ls` and `find` consume it — `find` searches all cached files when `--in` is absent).

**Subcommands** live in `src/cmd/{ls,find,library,mark,screenshot,assets,node_info,comments,cache}.rs`. `cache status` reports per-file payload age + sidecar presence, team catalogs, and mark count — offline, from metas + disk checks only. `node-info` is the curated single-target view designed for Claude Code agents implementing designs in code: layout/fills/strokes/effects/text/component/prototype, with referenced variables (short `vN` handles) and named styles hoisted to top-level blocks so descendants don't duplicate token data. Hidden children are pruned into `hidden_children` (`--include-hidden` restores), Figma defaults are elided, and descendant `bounds` are parent-relative. View shaping lives in `src/node_view.rs`; `scripts/node_info_lossless.py` diffs a curated view against `--raw` to prove nothing implementation-relevant was dropped. `comments` lists comment threads — all of a file's (replies inline, newest activity first, `--unresolved`/`--since` filters), those anchored under a node subtree, or one thread by `file:N:comm:M`; `--refresh` re-fetches a single file's comments via `cache::refresh_file_comments`. Shared comment shaping lives in `src/comment_view.rs`; `node-info` reuses it for its 10-newest-threads file summary and inline anchored comments. `library search` is the team-catalog plane — fuzzy text search across the published team library (components, component sets, styles), parity with the Figma MCP's `search_design_system`; each hit carries the component key and a paste-ready `file:N:x:y` when the source file is interned in `synth.json`. `mark` is the curated keyword→node plane (`add`/`rm`/`list`): it bypasses the resolver for `list` (reads `marks.json` directly) but `add` resolves each target through the resolver to capture a native-id stamp. Both `find` and `library search` call `marks::search_marks` and render ★-prefixed mark rows before their own hits; shared mark shaping (search, render, freshness) lives in `src/marks.rs`. `find` queries use a web-search grammar (`src/search_query.rs`): bare words = fuzzy tokens (implicit AND), `"quoted phrase"` = exact contiguous substring, uppercase `OR` = alternation binding tighter than AND, `-term` = chain-wide exclusion; `multi_token_search` (`src/node_search.rs`) consumes the parsed `Query` — one distinct ancestor per AND-group, phrases scored above same-length fuzzy hits.
