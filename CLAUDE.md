# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Workspace

Cargo workspace with three crates:

- **`figma-api/`** — autogenerated Rust client for the Figma REST API. **Do not hand-edit** `src/apis/` or `src/models/`; regenerate via `figma-api/scripts/regenerate.sh` (needs `npx` + JDK 11+). Drift fixes go in `openapi/patches/*.patch` or `scripts/postprocess.py`, not in the generated tree.
- **`figma-explorer/`** — the main CLI binary (`figma-explorer`). High-level navigation, screenshots, token/asset extraction, local cache.
- **`figma-get/`** — thinner read-only CLI over the same `figma-api` client.

## Commands

```bash
cargo build                                  # whole workspace
cargo build -p figma-explorer                # one crate
cargo test                                   # all unit tests
cargo test -p figma-explorer <name>          # single test by name substring
cargo fmt
cargo run -p figma-explorer -- <subcommand>  # run the CLI locally
```

The repo auto-loads `.env` via `dotenvy`, walking from cwd up to the filesystem root. The closest `.env` wins; ancestors fill in keys it didn't define. Required: `FIGMA_TOKEN`. Cache prefetch needs `FIGMA_PROJECTS_IDS` (comma-separated project IDs). Cache location override: `FIGMA_EXPLORER_CACHE_DIR` (else `dirs::cache_dir()`).

## Architecture — figma-explorer

**Tagged-ID grammar** (`src/id.rs`) is the one positional shape across every subcommand: `proj:N`, `file:N`, `file:N:x:y`, `file:N:comm:M`, bare `x:y` (native Figma node id), or a full figma.com URL. Synthetic small integers (`proj:N`, `file:N`) replace Figma's long opaque identifiers and are persisted in `<cache-root>/synth.json` so they stay stable across runs (gaps are never reused).

**Resolver** (`src/resolver.rs`) is the single entry point that turns an `Id` into a `ResolvedTarget` (Root/Project/File/Node). It wraps the cache, the `SynthState`, and a lazily-built `NodeIndex` (only constructed when a bare-node lookup actually needs it).

**Local cache** (`src/cache.rs`) stores a slimmed structural projection per file as `files/{file_key}.rkyv` plus a `.meta.json` sidecar. There is **no central manifest** — every piece of per-file state lives in its own sidecar so concurrent writers on disjoint files never share a write path. On-disk payload format: `[4-byte magic "FXC\0"][u32 LE version][rkyv body]`; version mismatch → silent refetch. rkyv archives are not endianness-portable; the cache is single-machine. Multi-repo coexistence: prune operations only touch metas whose `project_id` is in the current process's `FIGMA_PROJECTS_IDS`.

**Untyped JSON reads** (`src/cmd/mod.rs::fetch_file_json`): commands hit Figma's REST endpoint directly with `serde_json::Value` rather than going through `figma-api`'s typed deserializer, because real files routinely contain nodes the OpenAPI spec doesn't model. The cache projection (`CacheNode`) drops fields the structural commands don't need; live-data commands (`context`, `styles`, `screenshot`, `extract_assets`) still walk raw `Value` for access to `fills`/`strokes`/`characters`. See parallel APIs in `src/resolve.rs` (`pages` vs `pages_cache`, etc.).

**Global flags** (`Globals` struct in `lib.rs`) are threaded through every subcommand: `--json` (else compact YAML), `--cache-only` (refuse live API fallback), `--in <ID>` (scope override for bare-id resolution; only `ls` and `find` consume it).

**Subcommands** live in `src/cmd/{ls,find,comments,screenshot,tokens,assets,context,cache}.rs`. `context` is the aggregate — tree + screenshot + tokens + assets for a node.
